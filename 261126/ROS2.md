# 2026-11-26 — ReAct·Tool Use와 Waffle MPX 환경 설정

[13강 교안](<../ref/ROS2/13강. ReAct와 Tool Use · LLM과 VLA 로봇 실습.pdf>)과 [waffle-mpx-lyrical](https://github.com/SpartaPA/waffle-mpx-lyrical)을 참고했다. 오늘은 저장소를 clone하고 README 순서에 따라 Pi와 PC 설정을 진행했다.

## Pi와 PC를 나눠 설정하기

실습 구성은 TurtleBot3 Waffle Pi에 OpenMANIPULATOR-X와 센서를 연결하는 형태다. Pi는 센서·구동계를 연결하고, 제어 PC는 계획·조작·시각화 도구를 실행한다. GPU PC의 Isaac 실습은 별도 환경이다.

| 장치 | 자료에서 맡긴 역할 |
| --- | --- |
| Pi | OpenCR, 바퀴·팔·그리퍼, LiDAR·카메라, 로봇 TF |
| 제어 PC | 텔레옵, Cartographer, Nav2, MoveIt 2, RViz |
| GPU PC | Isaac Sim과 시각·언어 모델 실습 |

README 기준으로 저장소 자체가 워크스페이스의 `src`가 된다. clone 위치와 빌드 위치를 구분해야 한다. 새 터미널에서는 환경 파일을 읽고, 서로 통신할 Pi와 PC는 같은 ROS 도메인과 통신 가능한 네트워크를 사용한다. 실물과 시뮬레이션은 도메인을 분리한다. [README 설치 안내](https://github.com/SpartaPA/waffle-mpx-lyrical#배치와-설치).

```text
~/waffle_mpx/          ← 빌드하는 위치
└── src/              ← clone한 저장소
    ├── tools/
    └── ROS 패키지들
```

설정과 동작 확인은 구분한다. 다음 점검에서는 PC에서 센서 토픽이 들어오는지, 컨트롤러가 활성 상태인지 확인하면 된다. 아래는 설치 문서의 확인 명령이며, 오늘의 성공 로그를 뜻하지는 않는다.

```bash
ros2 topic hz /scan
ros2 topic hz /camera/color/image_raw
ros2 control list_controllers
```

[장치별 설치·첫 실행 문서](https://github.com/SpartaPA/waffle-mpx-lyrical/blob/main/docs/install.md)를 함께 참고한다.

## ReAct — 실행 결과를 보고 다음 호출 결정

어제는 작업을 나누고 선행 조건을 정의했다면, 오늘은 실행 중 들어오는 관측으로 다음 선택을 바꾸는 흐름이다.

```text
요청·이전 관측 → 도구 선택 → 인자·조건 검사 → 실행
                     ↑                      ↓
                     └──── 새 관측·오류 ─────┘
```

도구 선택 정책은 다음 호출을 고르고, 실행기는 등록된 도구와 인자를 검사해 실행한다. 결과를 관측으로 돌려받은 뒤 계속할지, 보류할지, 종료할지 결정한다. 규칙 기반 실행기도 비슷한 흐름을 만들 수 있지만, 그것만으로 LLM이 판단했다고 볼 수는 없다.

교안에서는 “1.5m 안에 물체가 있으면 사진을 찍어 줘”를 예로 든다. `read_scan`으로 유효 거리를 확인하고 조건에 맞으면 `take_photo`를 호출한다. “센서를 확인했다”는 문장보다 토픽·프레임·관측 시각·거리와 실제 저장 파일이 근거가 된다.

## LLM·VLM·VLA가 하는 일은 다르다

- **Qwen:** 한국어 요청에서 작업 종류와 거리를 추출한다.
- **시각·언어 정책:** RGB와 거리 조건을 바탕으로 촬영 여부를 선택한다. 실행기는 거리 조건을 별도로 검사한다.
- **색상 VLA:** 색상 지시와 관측을 받아 팔·그리퍼의 목표 궤적을 예측한다.

요청을 해석했다고 동작이 완료되는 것은 아니다. 촬영은 파일 저장, 이동은 피드백, 집기는 물체의 상승·안착 등으로 결과를 확인해야 한다. 교안의 Yes/No 로짓도 확률과 구분해서 읽는다.

## 실패 사유를 구분해서 기록

| 종료 사유 | 의미 |
| --- | --- |
| `outside_threshold` | 유효한 관측은 있지만 거리 조건 밖 |
| `timeout` | 새 센서 메시지를 받지 못해 거리 판단 불가 |
| `unknown_tool` | 등록되지 않은 도구 호출 |
| `budget_exhausted` | 다음 호출을 할 예산이 없음 |

수신 실패를 거리 0m로 바꾸면 “아주 가깝다”는 잘못된 판단으로 이어질 수 있다. 모르는 상태는 그대로 남겨야 한다. 또 LiDAR는 전체 방향의 최솟값을 읽고 전방 카메라는 일부 방향만 보므로, 가장 가까운 물체가 사진 속 물체와 같다고 단정할 수 없다. 센서 시각과 시야도 함께 확인해야 한다.

오늘 확인된 작업은 clone과 Pi·PC 설정이다. 교안에 제시된 촬영·차체 전진·색상 블록 운반 수치는 자료의 실행 사례이며 내 장비에서 측정한 결과로 기록하지 않았다.
