# 2026-11-23 — Transformer와 Attention

[11강 교안](<../ref/ROS2/11강. Transformer와 Attention.pdf>)과 수업 중 질문을 바탕으로 Q·K·V 계산, 헤드·블록·FFN, causal mask, KV cache와 TokenLearner를 정리했다. 두 토큰 계산과 FFN 계산은 이해를 위한 별도 예시다.

## Attention은 무엇에 주목할지 계산하는 과정

Attention은 현재 토큰을 표현할 때 다른 토큰의 내용을 얼마나 참고할지 정하는 연산이다. 관련 점수가 큰 위치의 내용을 더 많이 섞는다. Self-attention에서는 같은 입력에서 Query·Key·Value를 만든다.

| 구분 | 계산 | 역할 |
| --- | --- | --- |
| 입력 | X | 토큰마다 숫자 한 줄로 표현한 벡터 |
| Query | Q = XW_Q | 현재 위치가 찾는 단서 |
| Key | K = XW_K | 비교할 위치가 가진 단서 |
| Value | V = XW_V | 가중합으로 전달할 내용 |

W는 학습한 변환 규칙이고, Q·K·V는 현재 입력에 그 규칙을 적용한 결과다. Q·K 자체가 최종 점수는 아니며, Q와 K의 내적으로 위치 사이의 관련 점수를 계산한다. ‘단서’와 ‘내용’은 역할을 이해하기 위한 표현이다. 벡터의 각 차원에 단어 뜻이 하나씩 고정되는 것은 아니다.

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

### Attention이 곧 가중치인가?

가중치라고 생각했는데, Attention은 **비중을 계산하고 그 비중으로 Value를 섞는 과정 전체**다. Softmax 결과인 `[0.33, 0.67]`은 Attention 가중치이고, `0.33V₁ + 0.67V₂`는 Attention 출력이다.

여기서 학습한 가중치 W_Q·W_K·W_V와 구분해야 한다. 일반적인 추론에서 W는 고정되어 있지만, Attention 가중치는 현재 입력과 문맥에 따라 매번 계산된다.

## 두 토큰으로 직접 계산

입력과 투영 결과를 다음처럼 둔다. X는 단위행렬로 두었다. 따라서 이 예시에서는 W_Q·W_K·W_V의 값이 각각 Q·K·V에 그대로 나타난다.

```text
X = Q = [[1, 0],     K = [[0, 1],     V = [[2, 0],
         [0, 1]]          [1, 0]]          [0, 3]]
```

### 점수와 스케일링

Q의 각 행을 K의 각 행과 내적하면 다음 점수표가 나온다. 이번 K는 대칭이라 전치해도 같지만, 일반적으로는 반드시 K의 전치를 사용한다. 대칭 여부와 관계없이 각 점수는 q_i·k_j로 정의된다.

$$QK^T=\begin{bmatrix}0&1\\1&0\end{bmatrix},\qquad
\frac{QK^T}{\sqrt{2}}\approx\begin{bmatrix}0&0.7071\\0.7071&0\end{bmatrix}$$

Key 차원이 2이므로 √2로 나눈다. 차원이 커질 때 내적의 크기가 과도하게 커져 Softmax가 너무 뾰족해지는 것을 완화하는 조정이다.

### Softmax와 Value 가중합

Softmax를 **행별로** 적용한다. 첫 행은 두 번째 토큰에, 두 번째 행은 첫 번째 토큰에 더 큰 비중을 둔다.

$$A\approx\begin{bmatrix}0.3302&0.6698\\0.6698&0.3302\end{bmatrix}$$

$$AV\approx\begin{bmatrix}0.6605&2.0093\\1.3395&0.9907\end{bmatrix}$$

첫 번째 출력은 약 `0.330238 × [2,0] + 0.669762 × [0,3]`이다. 가중치를 먼저 0.33·0.67로 반올림하면 전달한 예시처럼 `[[0.66,2.01],[1.34,0.99]]`가 된다. 입력 두 토큰에서 나온 Value를 섞은 결과이며, 아직 좌표나 모터 명령은 아니다.

### Softmax가 모호한 지시를 편향시키는가?

Softmax는 점수를 양수로 바꾸고 합을 1로 맞춰 상대적 비중을 만든다. 원래 점수의 차이가 크면 한쪽에 비중이 몰리지만, 같은 점수라면 같은 비중이다. 모호한 지시를 스스로 명확하게 만드는 기능은 아니다.

특히 여기서 67%는 **정보를 섞는 가중치**이지, 대상이 맞을 확률이나 명령의 안전 확률이 아니다. 모델이 모호한 대상을 잘못 골랐다면 큰 가중치만 보고 실행할 수 없다. 대상 ID나 현재 관측을 확인하거나 사용자에게 다시 물어야 한다.

## Transformer는 행렬 계산의 이름인가?

행렬 계산은 Transformer를 구현하는 수단이고, Transformer는 **Attention을 중심으로 여러 연산을 묶은 신경망 구조**다.

- Attention: 토큰 사이의 정보를 결합한다.
- Multi-head: 서로 다른 W_Q·W_K·W_V로 계산한 결과를 합친다.
- FFN: 각 위치의 특징을 비선형 변환한다.
- 잔차 연결·정규화: 기존 정보를 전달하고 특징값을 조절한다.
- 위치 정보: 토큰 순서를 표현에 반영한다.

따라서 QKᵀ 한 번 계산한 것이 Transformer 전체는 아니다. 이런 계산을 블록으로 구성해 여러 층 쌓는다. 원 논문의 인코더·디코더 구성과 실제 LLM·VLA의 구성은 구분해서 봐야 한다.

## 토큰·헤드·블록을 혼동했던 부분

`거실의 / 빨간 / 컵을 / 주방으로 / 옮겨서 / 싱크대에 / 담아`처럼 토큰 7개로 나눴다고 가정한다. 실제 토큰화에서는 단어 하나가 더 잘게 나뉠 수 있다. 각 구절을 헤드나 블록에 배정하는 것이 아니다. 문장 전체의 표현이 블록 1을 거쳐 블록 2로 전달된다.

```text
7개 토큰의 벡터
 → 블록 1 [여러 헤드의 Attention → 결합 → FFN]
 → 블록 2 [여러 헤드의 Attention → 결합 → FFN]
 → … → 출력부
```

교안 15쪽과 원 논문 Figure 2에서처럼, 헤드 출력은 고정된 순서로 이어 붙여 W_O로 변환한다. `a+b+c`와 `b+a+c` 중 순서를 고르는 계산은 아니다. FFN도 블록이나 작업의 순서를 결정하지 않는다. 그림은 잔차 연결·정규화를 생략한 흐름이다. 원 논문의 디코더에는 인코더 출력을 참고하는 Attention도 추가된다.

### 같은 FFN인데 위치마다 출력이 다른 이유

같은 층에서는 모든 위치에 같은 FFN을 적용하지만, 각 위치의 입력 벡터가 달라 출력도 달라진다. 위치별이라는 말은 위치마다 따로 처리한다는 뜻이다. 토큰의 순서 정보는 별도로 반영한다. 층이 바뀌면 FFN의 파라미터도 달라진다. 원 논문 3.3절의 위치별 FFN은 두 선형 변환 사이에 ReLU를 둔다. 일반식은 `ReLU(xW₁+b₁)W₂+b₂`다.

행벡터 기준으로 편향을 생략한 계산 예시를 둔다. 실제 학습값이 아닌 수계산용 숫자다.

```text
FFN(x) = ReLU(xW₁)W₂

W₁ = [[1,-1,0],    W₂ = [[1,0],
      [0, 1,1]]          [0,1],
                        [1,1]]

‘컵을’ 위치: [2,1] → [2,-1,1] → ReLU [2,0,1] → [3,1]
‘빨간’ 위치: [0,1] → [0, 1,1] → ReLU [0,1,1] → [1,2]
```

Attention에서 다른 위치의 정보를 섞고, FFN에서 각 위치의 표현을 가공한다. 이 계산 자체가 로봇의 작업 순서를 검증해 주는 것은 아니다.

## Causal mask — 미래 토큰은 가리기

자기회귀 생성에서는 현재 위치가 자신과 앞선 위치만 참고하도록 제한한다. 예를 들어 `빨간 / 컵을 / 집어`에서 두 번째 위치는 아직 예측해야 할 뒤쪽의 `집어`를 볼 수 없다.

Softmax 전에 점수표의 미래 위치에 −∞를 더하면 그 위치의 가중치는 0이 된다.

```text
세 토큰의 마스크 M:
[[0, -∞, -∞],
 [0,  0, -∞],
 [0,  0,  0]]

A = softmax(QKᵀ / √d_k + M)
```

학습 때는 문장 전체가 입력에 있어도 미래 정답을 미리 보지 않게 해야 실제 생성 조건과 맞는다. 위치 정보가 “몇 번째 토큰인가”를 알려준다면, 마스크는 “어디까지 참고할 수 있는가”를 정한다. 모든 Attention이 causal인 것은 아니며 양방향 self-attention은 앞뒤를 모두 참고한다.

위 두 토큰 예시는 마스크 없는 계산이다. 같은 점수에 causal mask를 적용하면 첫 행은 `[1,0]`이 되어 첫 토큰의 출력은 `[2,0]`이고, 둘째 행은 앞의 계산과 같다.

### 정답을 가린다는 뜻

학습 목표는 ‘빨간’에서 ‘컵을’, ‘빨간 컵을’에서 ‘집어’를 예측하는 것이다. 뒤에 있는 정답을 직접 참고해 복사하지 못하게 가린다. 정답은 예측 후 손실 계산에 사용한다. 전체 문장을 넣고 여러 위치를 병렬 학습하되, 각 위치의 참고 범위는 제한한다. 이것이 돌발상황 대응 능력을 직접 보장하지는 않는다.

## VLA로 연결해서 이해하기

영상과 지시는 모델 구조에 맞게 토큰·특징으로 표현되고, Attention을 거치며 서로 관련된 정보를 결합한다. 위 2×2 행렬은 원리 설명용이지 실제 영상·문장이 만드는 텐서 크기는 아니다.

```text
영상·지시 → 특징 결합 → 행동 출력부 → 행동 복원·변환 → 실행 검사 → 로봇
```

Action Head는 최종 특징을 행동 표현으로 바꾸는 출력부로 이해할 수 있다. 다만 모든 VLA가 같은 출력부를 쓰지는 않는다. RT-2·기본 OpenVLA처럼 행동 토큰을 예측하고 복원하는 방식도 있고 연속 행동값을 출력하는 방식도 있다.

예를 들어 위치 증분 3개·회전 증분 3개·그리퍼 1개를 출력하도록 정했다면 7차원 행동이다. 이것이 관절각 7개라는 뜻은 아니다. 출력 숫자를 실행하기 전에 역정규화, 단위·좌표계, 절대값/증분, 로봇 한계와 현재 상태를 맞춰야 한다. “사과를 먹다” 같은 문장을 넣는다고 로봇이 실행할 수 있는 작업이 되는 것도 아니다.

## 긴 입력과 로봇 정책으로 이어 보기

### KV cache — 계산한 K·V 재사용 (교안 16쪽)

전체 입력 길이가 T이면 한 헤드의 점수표는 T×T다. 토큰이 128개에서 256개로 늘면 점수 개수는 16,384개에서 65,536개로 늘어난다.

자기회귀 생성에서는 이전 위치의 K·V를 층별로 저장한다. 새 토큰의 Q로 과거 K를 비교하고 새 K·V를 캐시에 추가한다. 앞부분을 매번 다시 계산하지 않아도 되지만, 문장이 길어질수록 캐시 메모리와 참고할 위치는 늘어난다. 기본 KV cache는 정보를 압축하는 방식이 아니라 계산 재사용이다.

### 지시·관측과 RT-1 평가 (교안 17~18쪽)

“빨간 컵을 집은 뒤 선반에 놓아”에서 대상은 빨간 컵, 목적지는 선반, ‘뒤’는 작업 순서의 단서다. 이 정보를 로봇 정책에 넣으려면 영상·언어·로봇 상태가 각각 어떤 인코더를 거쳐 어떤 크기의 특징이 되는지 확인해야 한다. 특정 헤드가 색이나 순서를 전담한다고 단정할 수는 없다.

처음에는 Transformer가 구절의 순서를 정하는 모델이라고 생각했다. 원 논문은 Attention으로 입력 사이의 관계를 계산하고 번역 문장을 생성하는 구조를 제안한 것이다. 문장 속 단어 순서, 출력 생성 순서, 로봇의 작업 순서는 구분해서 봐야 한다.

RT-1은 실제 로봇의 여러 작업 데이터로 학습한 정책이다. 교안 18쪽은 데이터의 양·다양성·모델 규모에 따른 일반화 평가를 소개한다. 학습용 공간과 평가용 주방의 물체·배치 차이처럼, 어떤 조건이 달라졌는지를 보고 결과를 읽어야 한다.

## TokenLearner는 오차를 감수한 단순화인가?

19쪽의 TokenLearner는 영상에서 뽑은 많은 특징을 적은 수의 토큰으로 요약하는 학습 모듈이다. RT-1은 언어 지시로 영상 특징을 조절한 뒤, 이미지당 81개 특징 토큰을 8개로 줄여 Transformer에 전달한다. 문장의 81개 단어 중 8개를 고르는 뜻은 아니다. [RT-1 연구팀 설명](https://research.google/blog/rt-1-robotics-transformer-for-real-world-control-at-scale/).

```text
영상 + 지시 → 지시를 반영한 영상 특징 → TokenLearner → 적은 토큰 → Transformer
```

각 요약 토큰이 영상의 어느 부분을 얼마나 반영할지 학습한다. 단순히 앞의 몇 개만 남기거나 모든 영역을 똑같이 평균내는 것이 아니다. 배경보다 작업에 필요한 물체·공간의 정보를 남기는 방향으로 배울 수 있다. [TokenLearner 논문](https://arxiv.org/abs/2106.11297).

“계산을 줄이려고 정보를 요약한다”는 이해는 맞다. 다만 정해진 오차를 허용하고 숫자를 대충 계산하는 방식과는 다르다. 학습으로 필요한 표현을 남기려는 것이고, 정보 손실이나 작은 물체의 단서를 놓칠 가능성은 있다. 실제 성능을 유지하는지는 평가로 확인해야 한다.

KV cache는 기존 K·V의 재사용이고, TokenLearner는 토큰 표현 자체의 요약이다. 둘 다 계산 부담을 줄이지만 작동 방식이 다르다.
