## 학습 내용

대화 개요의 ‘클러스터링’은 저장과 분산 시스템 문맥에 배치되어 있다. 따라서 여러 노드를 함께 운영하는 클러스터 구성으로 해석해 설명하되, 원본에서 데이터 분석의 군집화를 뜻했는지는 확인해야 한다.

| 개념 | 핵심 역할 | 구분해야 할 점 |
| --- | --- | --- |
| 클러스터 | 여러 노드를 묶어 시스템 운영 | 분석 기법인 군집화와 문맥 구분 |
| 샤딩 | 데이터를 나누어 서로 다른 노드에 배치 | 데이터 분할이 목적 |
| 복제 | 같은 데이터를 여러 위치에 보관 | 복사본 관리와 일관성 고려 |
| NoSQL | 관계형 테이블 중심 방식 이외의 다양한 저장 모델 | 모든 제품이 같은 구조·보장을 제공하지 않음 |

샤딩과 복제는 함께 사용할 수 있다. 데이터를 분할한 각 영역에 복제본을 두는 식으로 저장 규모와 장애 대응을 모두 고려할 수 있다. 다만 복제본이 있다는 사실만으로 삭제·오염에서 안전한 백업이 확보되는 것은 아니다.

CAP는 분산 시스템의 일관성(Consistency), 가용성(Availability), 네트워크 분할에 대한 내성(Partition tolerance)을 다룬다. **네트워크 분할이 발생한 상황에서 일관성과 가용성을 동시에 보장할 수 없다는 제약**이 핵심이다. 이를 아무 상황에서나 세 항목 중 두 개를 고르는 규칙으로 단순화하지 않는다. 여기서 가용성은 일반적인 서비스 가동률과, 일관성은 ACID의 일관성과 동일한 의미로 사용되는 용어가 아니다.

ACID는 트랜잭션의 다음 성질을 뜻한다.

| 성질 | 개념 |
| --- | --- |
| Atomicity | 트랜잭션의 전부가 반영되거나 전부가 반영되지 않음 |
| Consistency | 정의된 데이터 제약을 만족하도록 유효한 상태 유지 |
| Isolation | 동시 트랜잭션의 상호 영향 제어; 보장 수준은 격리 수준에 따라 다름 |
| Durability | 성공적으로 완료된 트랜잭션 결과의 지속성 |

BASE는 Basically Available, Soft state, Eventual consistency로 표현되는 접근이다. 최종 일관성은 갱신이 더 발생하지 않는 등의 조건에서 복제본이 같은 상태로 수렴하는 성질로 이해한다. ACID와 BASE를 모든 데이터베이스가 반드시 둘 중 하나에만 속하는 단순한 제품 분류로 사용하지 않는다. NoSQL이라는 이름만으로 트랜잭션 지원이나 일관성 수준을 확정할 수 없다.

## 학습한 점

- 데이터를 나누는 샤딩과 복사본을 만드는 복제를 구분한다.
- 저장 기술은 데이터 형태뿐 아니라 질의와 일관성 요구를 보고 선택한다.
- CAP와 ACID에서 같은 단어를 쓰더라도 정의와 문맥을 구분한다.
