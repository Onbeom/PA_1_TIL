## 1강 AI 발전 흐름과 신경망·LLM 기초
- 규칙을 사람이 쓰는 것(조건문) vs 사례로 파라미터를 찾는 것(머신러닝). 여러 층으로 특징을 바꾸는 신경망을 쓰면 딥러닝 (ML ⊃ DL)
- 뉴런: $z = w_1x_1 + w_2x_2 + b$ → 활성화
  - 예: $x=(2,1)$, $w=(0.5,-1)$, $b=0.2$ → $z=0.2$, ReLU 0.2 / $x_2=3$이면 $z=-1.8$ → 0
- 층의 파라미터 수 $= d_{in} \times d_{out} + d_{out}$ → 입력 2, 은닉 2, 출력 1이면 4+2+2+1 = 9개
- 비선형 활성화가 필요한 이유: 선형만 쌓으면 $W_2(W_1x+b_1)+b_2$가 다시 하나의 선형 → XOR를 못 나눔

| 구분 | 하는 일 | 가중치 |
|---|---|---|
| 추론 | 정해진 파라미터로 출력 계산 | 안 바뀜 |
| 학습 | 순전파 → 손실 → 역전파 → 갱신 | 바뀜 |

- 갱신 한 번: $L=(wx-y)^2$, $x=2, y=4, w=1$ → $L=4$, $\partial L/\partial w = 2(wx-y)x = -8$, $\eta=0.1$ → $w=1.8$, $L=0.16$
  - $\eta=1$이면 $w=9$, $L=196$ → 학습률이 크면 오히려 나빠짐
  - 기울기가 음수면 $w - \eta g$에서 $w$가 **커짐** (손실이 커지는 방향의 반대로 이동)
- 역전파 = 연쇄법칙. 유한차분 $\frac{L(w+\epsilon)-L(w-\epsilon)}{2\epsilon}$으로 자동미분 값을 검산 (ε가 너무 크면 곡률 오차, 너무 작으면 부동소수점 오차)
- 시그모이드 + 교차 엔트로피면 $\partial L/\partial z = p - y$
- 입력 명세: shape(영상 `[B,C,H,W]`)만으로는 부족 → dtype·단위(deg/rad)·좌표계·센서 순서·시각까지 적음. 정규화는 학습 때 통계를 추론에도 그대로
- 데이터 분할: 학습(갱신) / 검증(설정 선택) / 시험(최종 보고). 로봇 영상은 프레임이 아니라 수집 회차·물체·환경 단위로 나눔 ([261029](../261029/ROS2.md) 분할과 누수)
- LLM: 문장 확률 = $\prod_t p(x_t \mid x_{<t})$, 다음 토큰을 하나씩 생성 → 출력이 길수록 지연 증가
  - 프롬프트에 예시를 넣는 것은 **입력 변경**, 파인튜닝은 **가중치 갱신**

| 이름 | 무엇을 가리키나 | 입력 → 출력 |
|---|---|---|
| CNN, Transformer | 구조 | — |
| LLM | 과제·데이터 | 토큰 → 다음 토큰 |
| VLM | 과제·데이터 | 영상 + 언어 → 언어 |
| VLA | 과제·데이터 | 관측 + 언어 → 행동 ([261019](../261019/ROS2.md#vla)) |

- Physical AI는 닫힌 고리: 관측 → 행동 → 다시 관측. 관측 $o_t$ ≠ 실제 상태 $s_t$ (가려진 손잡이, 마찰)
  - 상위 모델은 목표·행동 **후보**를 만들고, 실행기가 단위·좌표계·관절 한계·현재 상태를 검사

## 2강 환각과 문맥의 한계
- 다음 토큰 예측 ≠ 사실 확인 → 생성과 검증을 따로 설계
- 실패를 다 "환각"으로 부르면 원인을 못 찾음

| 사례 | 입력 근거 | 출력 | 먼저 볼 곳 |
|---|---|---|---|
| 미등록 대상 생성 | A만 있음 | B로 이동 | 허용 목록·의미 검증 |
| 옛 관측 사용 | 최신엔 장애물 | 통로 비어 있음 | 관측 시각·재조회 |
| 좌표 혼동 | map 좌표 | base_link로 실행 | 어댑터·TF |
| 검색 누락 | 규정 못 찾음 | 규정 위반 | 검색 결과 |

- temperature: $p_i = \frac{e^{z_i/T}}{\sum_j e^{z_j/T}}$, $\frac{p_i}{p_j} = e^{(z_i - z_j)/T}$
  - 로짓 [2, 1]: $T=1$ → 0.731, $T=0.5$ → 0.881. 틀린 후보가 1등이면 **틀린 답의 확신만 커짐**
  - "항상 같은 답" ≠ "항상 맞는 답"
- 판정은 실행 / 확인 질문(모호) / 재관측(오래된 관측) / 거부(금지 작업)로 나눔
- 보류가 많으면 안전하지만 일을 못 함 → 두 지표를 같이 봄
  - coverage = 실행한 비율, selective risk = 실행한 것 중 오답 비율
  - 20건 중 12건 실행, 1건 오답 → 60%, 8.3%. 전부 보류하면 coverage 0
- 비용으로 본 실행 문턱: 성공확률 $q$가 $q \ge 1 - C_{확인}/C_{실패}$일 때만 실행 ($C_{실패}=100$, $C_{확인}=5$면 0.95)
  - $q$는 검증 세트로 보정한 값. 모델이 말하는 "95% 확신"을 그대로 넣지 않음
- 문맥: 창에 들어갔다고 잘 쓰는 건 아님 → 길이와 근거 위치를 **따로** 바꿔 실험. 실행 직전에는 상태를 다시 조회
- 정답 판정표는 실험 **전에** 작성 (응답을 보고 바꾸면 모델에 유리해짐)

## 3강 제로샷·원샷·퓨샷 비교
- 샷 = 입력 안의 예시: $p_\theta(y \mid x, D)$, $\theta$는 고정 → 원샷의 "1"은 학습 스텝이 아님
- 예시는 형식만이 아니라 **판단 경계**를 알려 줘야 함

| 종류 | 입력 | 목표 출력 |
|---|---|---|
| 정상 | 등록된 A로 이동 | move, A |
| 모호 | 저쪽으로 가 | clarify (대상 질문) |
| 미등록 | 지도에 없는 Z | hold, unknown_target |
| 상태 충돌 | 막힌 B로 이동 | hold, blocked |

- 공정한 비교: 모델·규칙·스키마·생성 설정·채점기를 고정하고 예시만 바꿈. 예시 순서도 변수 (3개면 3! = 6가지)
- 누수 금지: 시험 문장(또는 거의 같은 문장)을 예시에 넣지 않음. 개발 사례로 다듬고 시험 사례는 마지막에만
- 퍼센트포인트 vs 퍼센트: 70% → 85%는 15%p, 상대 증가 21.4%
- 같은 사례끼리 짝지어 개선·퇴행 사례를 따로 읽음. 예시가 늘린 토큰·지연도 함께 보고

## 4강 CoT와 작업 분해
- 작업 분해 = 문장을 잘게 나누기가 아니라 단계마다 **전제조건**과 **완료조건(관측 증거)**을 정하기
  - 집기 완료 = "손 닫기 명령 전송"이 아니라 파지 센서·물체 동반 이동 확인
- 계획(앞으로 할 일) ≠ 실행 상태(관측한 사실): pending → running → succeeded / failed. 실패한 단계 뒤의 의존 단계는 시작하지 않음
- CoT: 긴 중간 설명이 정확한 계획을 뜻하지 않음 → 외부에서 확인할 수 있는 짧은 계획·조건만 받음 ("안전하다고 판단함"은 검사 기준이 없음)
- 행동을 조건과 효과로: $\mathrm{Pre}(a) \subseteq S$일 때만 실행, $S' = (S \setminus \mathrm{Del}(a)) \cup \mathrm{Add}(a)$
  - 실물은 효과가 확실하지 않음 → 예상 효과를 상태에 그냥 반영하지 말고 관측으로 확인 후 갱신

| 행동 | 전제조건 | 기대 효과 | 관측 증거 |
|---|---|---|---|
| pick | 대상 근처, 손 비어 있음 | holding(box) | 파지, 물체 동반 이동 |
| move | 경로 유효 | at(robot, B) | 목표 오차, 속도 0 |
| place | 파지 중, 놓을 곳 유효 | at(box, B) | 손 비어 있음, 물체 위치 |

- 부분 순서 계획(DAG): 필요한 의존 관계만 둠. 단 같은 팔·카메라·통로를 쓰면 독립이어도 동시 실행 불가 → 의존 관계와 자원 잠금을 따로 기록
  - 예: 인식 3s ∥ 경로 조회 2s → 집기 4s → 이동 6s: 임계 경로 3+4+6 = 13s (단순 합 15s)
- SayCan식 스킬 선택: 목표 유용성 × 실행 가능성
  - 스펀지 집기 0.9 × 0.1 = 0.09 < 스펀지 찾기 0.6 × 0.8 = 0.48 → 찾기 먼저 (교안 가상 예시)

```python
deps = {"observe": [], "approach": ["observe"], "pick": ["approach"], "carry": ["pick"]}
status = {k: "pending" for k in deps}
def ready(task):
    return status[task] == "pending" and all(status[p] == "succeeded" for p in deps[task])
status["observe"], status["approach"] = "succeeded", "failed"
assert not ready("pick") and not ready("carry")   # 접근 실패 → 집기·운반 보류
```

- 프로젝트와 연결: 미션의 접근 → 집기 → 놓기 상태 기계([261030](../261030/ROS2.md))와 같은 구조. 집기 판정을 명령 응답이 아닌 쥠 판정(#201)으로 요청했던 것이 "완료조건 = 관측 증거"

## 확인 문제 (내 답)
1. 추론 때 고정하는 것은 $w$와 $x$ 중 무엇? → $w$ (입력 $x$는 매번 바뀜)
2. $T=0.5$가 $T=1$보다 사실성을 보장하나? → 아니요. 1등 후보에 더 몰릴 뿐, 그 후보가 맞는지는 식에 없음
3. 접근이 failed인데 집기를 시작해도 되나? → 안 됨. 재관측·재계획으로 감
