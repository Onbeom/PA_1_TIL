# 2026-11-27 — 명령 계약, VLA 행동 후보와 RAG

[14–18강 교안](<../ref/ROS2/14–18강. 명령 계약에서 통합 플래너 평가까지 · Waffle MPX 실습.pdf>)의 **1~74쪽**과 수업 중 메모·질문을 정리했다. 예제는 [waffle-mpx-lyrical](https://github.com/SpartaPA/waffle-mpx-lyrical)이다. 75쪽부터의 통합 플래너 평가는 이번 범위에서 제외했다. 아래 수치와 실행 사례는 교안의 기록이며 내 장비에서 측정한 결과는 아니다.

## 1. 명령 계약과 ROS 2 Action

명령은 숫자만 맞으면 되는 것이 아니라 필드 형식, 단위, 좌표계, 관측 시각까지 맞아야 한다.

- `request_id`: 요청 하나의 식별자. 실행 기록과 대조해 중복 실행을 막는 데 사용한다. 하위 작업 ID와 반드시 같은 것은 아니다.
- `unit`: 수치의 단위. m와 mm를 혼동하면 1,000배 차이가 난다.
- `age_s`: 관측부터 사용 시점까지 경과한 시간. 예제는 0~0.4초를 허용한다.
- NaN·무한대는 유효한 좌표가 아니다. 단위 오류나 누락이 있으면 NaN을 명령으로 내보내는 것이 아니라 **요청을 거부하고 원인을 반환**해야 한다.

### Action 용어 정리

| 항목 | 의미 |
| --- | --- |
| Goal | 서버에 실행을 요청하는 목표 |
| Goal Handle | 수락된 목표를 가리키며 결과 조회·취소에 사용하는 핸들. 목표 방향을 뜻하지 않음 |
| 비동기 호출 | 응답이 오기 전에 제어 흐름을 돌려주는 방식. 서버 가용성이나 요청 수락을 보장하지 않음 |
| Future | 나중에 완료될 결과·예외를 다루는 객체 |
| Callback | 지정한 사건에 반응하는 함수. 피드백 콜백은 피드백 수신 시 호출됨 |
| `status` | 목표의 생애주기상 현재·종료 상태 |
| `error_code` | 해당 Action의 결과에 정의된 코드 |
| `cancel` | 취소 요청. 수락과 최종 취소 상태, 실제 정지 시점은 구분 |

종료 상태와 결과 코드를 함께 읽어야 한다. 교안에서는 취소 결과가 `status=5`, `error_code=0`이므로 오류 코드만 보고 성공으로 처리하면 안 된다. 기다리다 timeout이 나도 목표 자체가 끝났다는 뜻은 아니다. 결과 미확정 상태와 마지막 관측 시각을 남기고 중복 요청을 피한다.

### 0.1200 rad 목표에 0.1192 rad면 더 움직이면 되지 않을까?

잔차는 0.0008 rad, 약 0.046°다. 피드백으로 오차를 줄이는 제어는 가능하지만, 센서 분해능·잡음·마찰 때문에 오차를 정확히 0으로 만들 때까지 보정하면 진동하거나 끝나지 않을 수 있다. 일반적으로 위치·속도·시간의 허용 조건을 정한다.

다만 교안의 마지막 피드백 값만으로는 이 시험의 정확한 성공 판정 조건이나 이후 유지 동작을 확정할 수 없다. **마지막 관측과 성공 결과를 구분하고 허용 오차·시각을 확인해야 한다.** 작은 잔차가 남았다는 사실만으로 피드백이 없다고 결론 내릴 수는 없다.

## 2. 멀티모달 표현과 Grounding

모달리티는 정보의 형태이고, 멀티모달 모델은 영상·언어 등 다른 형태를 함께 처리한다. 임베딩은 입력을 숫자 벡터로 표현한 것이다. Grounding은 “파란 블록”이라는 말이 **현재 관측의 어느 물체·위치에 해당하는지** 연결하는 과정이다. 입력값 하나를 단순 선택하는 것보다 대상·공간과 연결한다는 의미가 중요하다.

색만으로 후보가 여러 개면 다시 확인한다. 색을 찾았어도 유효 깊이가 없으면 좌표를 보류한다. 교안의 색상 기준선처럼 사람이 정한 벡터와 학습된 VLM 임베딩도 구분한다.

픽셀과 깊이를 카메라 좌표로 복원한 뒤 로봇이 쓰는 좌표계로 바꾼다.

$$X=(u-c_x)Z/f_x,\quad Y=(v-c_y)Z/f_y,\quad p_{world}=Rp_{optical}+t$$

깊이 Z는 이 식에서 광축 방향 거리다. 복원한 표면 대표점이 물체 전체의 중심과 같지는 않으며, 깊이 단위와 변환 방향도 확인해야 한다.

## 3. 인코더와 은닉층에 대한 오해

인코더는 여기서 암호화 장치가 아니다. 영상·문장을 모델이 사용할 특징으로 바꾸는 부분이다. 디코더·출력부는 이 표현으로 문장이나 행동을 예측한다. 고유 벡터를 보고 임의로 문자를 배정하거나 원문을 반드시 복원하는 방식은 아니다.

은닉층도 내부 구조를 아무도 모르는 미지의 연산이 아니다. 예를 들어 `h = ReLU(xW+b)`의 구조·가중치·출력은 확인할 수 있다. ‘은닉’은 입력과 최종 출력 사이의 내부 층이라는 뜻이다. **계산을 안다는 것과 학습된 특징의 의미를 사람이 모두 해석할 수 있다는 것은 다르다.**

교안 43쪽의 은닉값은 내부 층의 출력이다. 특징 벡터를 노름으로 나누는 과정은 크기를 맞추면서 방향을 유지한다.

## 4. Waffle 색상 정책은 무엇을 합칠까?

```text
RGB + 언어 지시 → SmolVLM2 특징 + 로봇 상태 → 부모 행동 헤드의 특징
                                                            +
                                               선택한 색 영역의 기하 특징
                                                            ↓
                                                    궤적 회귀 헤드
                                                            ↓
                                                     92시점 × 7축
```

‘부모 VLA 값’은 부모 모델의 내부 특징을 가져온다는 뜻이다. 색 영역의 중심·크기 등 기하 특징을 추가로 결합한다. RGB에 색 정보가 들어 있으므로 VLA가 위치만 쓰고 색은 전부 HSV로만 처리한다고 볼 수 없다. 정확한 색 분할 연산은 구현을 따로 확인해야 한다.

RGB-D 카메라를 쓴다고 정책 입력에도 깊이가 반드시 들어가는 것은 아니다. 이번 교안의 정책 경로는 RGB·지시·상태를 사용하고, RGB-D의 깊이는 3차원 Grounding 경로에서도 사용한다.

### 행동 어댑터와 피드백

어댑터는 출력을 제어기 입력에 맞추며, 이 실습의 `adapt()`는 축 순서·일곱 값의 유한성·범위·차체 정지 조건도 검사한다. 모든 충돌·안전 검사가 어댑터 하나에서 끝나는 것은 아니다.

행동 순서는 차체 선속도·회전속도, 팔 절대각 4개, 그리퍼 위치다. 역정규화 후에도 각 축의 단위와 범위를 맞춰야 한다. 교안 예시에서 정규화된 그리퍼 값 0은 물리 위치 0이 아니라 범위의 중간값 0.0045 m다.

상위 색상 정책은 첫 관측으로 전체 궤적을 한 번 예측한다. 하위 실행기는 관절 위치를 다시 읽고 허용 변화량을 제한한다. **상위 열린 루프와 하위 피드백이 한 시스템에 함께 있을 수 있다.** 물체가 밀린 상황까지 대응하려면 상위에서도 재관측·재계획이 필요하다.

롤아웃은 정책을 전개해 얻는 관측·행동의 연속 기록이다. 시작부터 종료까지의 한 시험은 에피소드이며, 롤아웃은 전체 에피소드 또는 일부 구간일 수 있다.

## 5. 미세조정·동결·LoRA

- **Fine-tuning:** 기존 모델을 새 과제·도메인 데이터에 맞게 추가 학습한다.
- **Freeze:** 선택한 가중치를 학습 중 갱신하지 않고 유지한다. 모델 계산 전체를 중단하는 뜻은 아니다.
- **LoRA:** 기존 W를 동결하고 저랭크 변화량 BA를 학습한다. 기존 가중치 중 필요한 항목만 골라 갱신하는 방식과 다르다.

512×512 행렬 전체는 262,144개 값이다. r=8인 LoRA의 두 행렬은 512×8 + 8×512 = 8,192개 값으로 변화량을 표현한다. **이번 색상 체크포인트는 LoRA가 아니라 부모 특징 위에 궤적 회귀 헤드를 학습한 예제**다.

모방학습을 강화학습의 초기 정책이나 시연 데이터로 활용하면 탐색을 도울 수 있다. 다만 ‘강화학습의 인자’ 하나로 보는 것은 부정확하고, 학습 시간 감소나 다른 비용 증가도 항상 성립하지 않는다. 시연 수집 비용, 분포 차이와 실제 평가를 함께 봐야 한다.

## 6. VLA 추가 연구 — 대상 표현과 행동 생성

추가 자료는 공식 연구 소개와 초록 중심으로 읽었다. Waffle 예제에 아래 알고리즘이 모두 구현되어 있다는 뜻은 아니다.

| 자료 | 핵심 아이디어 | 오늘 내용과의 연결 |
| --- | --- | --- |
| [SlotVLA](https://slot-vla.github.io/) | 물체를 slot으로 요약하고 집게·대상 등의 관계 토큰을 함께 사용 | 배경과 대상이 뒤섞인 표현 대신 작업에 필요한 물체·상호작용을 압축 |
| [ACoT-VLA](https://arxiv.org/abs/2601.11404) | 명시적인 거친 참조 궤적(EAR)과 내부 행동 사전정보(IAR)로 행동 출력을 조건화 | 긴 설명만 생성하기보다 행동 공간에서 중간 단서를 마련 |
| [XCoT-VLA](https://arxiv.org/abs/2608.10976) | 자율주행에서 짧은 실행 지향 추론 토큰을 궤적 생성에 연결 | 추론 토큰과 궤적 질의에 서로 다른 FFN을 적용하고 지연을 고려 |

Slot은 대상을 요약한 표현, Attention은 관련 특징을 모으는 연산이다. 관계 토큰은 대상 사이의 상호작용을 담고 디코더는 이를 받아 필요한 출력을 계산한다. 모든 VLA가 이 구조를 사용하는 것은 아니다.

SlotVLA 공식 소개에서는 물체 중심 과제의 장점과 함께 공간·장기 과제에서 남은 한계도 제시한다. 압축했다고 모든 상황에서 더 잘하는 것은 아니다. 또 이 페이지의 LIBERO+ 데이터셋과 교안의 LIBERO-Plus 견고성 벤치마크는 이름만 보고 같은 자료로 취급하지 않는다.

ACoT-VLA는 로봇 조작, XCoT-VLA는 자율주행을 다룬다. 연구 조건이 다르므로 논문 결과를 우리 로봇의 성공률이나 즉시 적용 가능성으로 바꾸어 해석하지 않는다.

## 7. RAG — 작업 규칙을 검색하고 인용 확인

RAG는 Retrieval-Augmented Generation, **검색 증강 생성**이다. 외부 문서에서 근거를 찾아 질문과 함께 모델에 제공하고 답을 생성한다. 검색된 내용을 가중치에 영구 학습하는 것과는 다르다.

- `query`: 검색하려는 질문.
- `chunk`: 독립적으로 검색할 문서 조각. 질문을 나눈 조각이라는 뜻은 아니다.
- **희소 검색:** 단어 일치 등을 사용. 수업 코드는 검색어 교집합의 크기로 점수를 계산한다.
- **밀집 검색:** 학습한 벡터의 유사도로 검색. 동의어에 유리할 수 있지만 버전·의미 혼동은 남는다.
- **필터:** 장비·문서 버전 등 조건으로 후보를 제한.
- **top-k:** 순위가 높은 k개를 선택. k를 늘리면 불필요한 근거와 입력 길이도 늘 수 있다.

```text
질문·버전 → 필터·검색 → 근거 조각 → Qwen의 답변
                                      ↓
                        반환 ID와 인용문을 원문에 대조
```

근거(evidence)는 판단을 뒷받침할 자료이고 quote는 원문에서 가져온 문구다. `answer()`는 예제 함수 이름이며, 반환 ID가 조회 결과에 있는지와 인용문이 해당 원문의 부분 문자열인지 검사한다.

| 상태 | 이 예제에서 뜻하는 것 |
| --- | --- |
| `cited` | 문서 ID·인용문 대조 통과 |
| `unsupported` | 인용 검증 실패 |
| `no_evidence` | 검색된 근거가 없어 생성 전 종료 |

`cited`라도 질문과 무관한 문장을 인용했을 수 있다. **인용 일치, 답변의 정확성, 현재 로봇의 조건 충족은 따로 확인**한다. 매뉴얼에서 “0.5초 이상 안착”을 찾았다는 사실과 실제 블록이 그만큼 안정됐다는 사실은 다르다.

검색과 답변 평가도 나눈다. 교안의 가상 예시에서 10개 질문 중 근거를 찾은 것이 8개이고 그중 정답이 6개라면 검색 적중률 80%, 조건부 정확도 75%다. 나머지 두 질문도 오답이면 종단 간 정확도는 60%다. 75%만 보고하면 검색 누락이 가려진다.

문서 조각에는 ID·버전·원문을 남겨야 한다. 로봇 상태는 문서가 아니라 최신 관측으로 확인하고, 필요한 근거가 없으면 추측으로 실행 조건을 채우지 않는다.
