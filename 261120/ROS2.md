# 2026-11-20 — 영상과 언어를 로봇 행동으로: RT-2와 OpenVLA

[AI·LLM 응용 베이스 v1.2](<../ref/ROS2/01 AI·LLM 응용 베이스 · 20시간 · v1.2.pdf>) 35~63쪽. 오늘은 로컬 LLM 오류 진단부터 CNN·VLM을 거쳐 VLA까지 배웠다. RT-2와 OpenVLA가 영상과 지시를 어떻게 행동으로 연결하는지에 초점을 맞췄다.

## LLM·VLM에서 VLA로

“빨간 상자를 옮겨”라는 지시를 이해하는 것과 실제로 집는 것은 다른 문제다.

| 구분 | 입력 → 출력 | 로봇에서 맡는 역할 |
| --- | --- | --- |
| LLM | 문장·상태 → 문장·계획 | 작업을 나누고 다음 할 일 결정 |
| VLM | 영상·언어 → 설명·표현 | 장면과 대상 이해 |
| VLA | 영상·언어 등 관측 → 행동 | 학습한 정책으로 움직임 출력 |

VLA는 관측과 지시를 받아 행동을 내는 정책으로 볼 수 있다.

$$a_t = \pi(o_t, l)$$

여기서 행동이 무엇인지를 먼저 정해야 한다. 관절 목표값인지, 로봇 손끝(TCP)의 위치·회전 증분인지에 따라 같은 숫자도 의미가 달라진다.

## RT-2 — 행동도 토큰으로 표현

RT-2(2023)는 영상·언어 모델에 로봇 행동 데이터를 연결한 VLA다. 웹의 영상·언어 과제와 로봇 시연 데이터를 함께 사용해 학습한다. 핵심은 **로봇 행동을 토큰으로 표현해 예측한다는 것**이다.

```text
현재 영상 + “상자를 집어”
          ↓
      행동 토큰 예측
          ↓
로봇 행동값으로 복원 → 제어 → 새 영상 관측
```

언어 토큰은 문장을 표현하지만 행동 토큰은 움직임을 표현한다. 숫자처럼 보이는 토큰을 그대로 모터에 보내는 것이 아니라 정해진 행동 규격으로 복원해야 한다.

사전학습에서 얻은 의미 이해를 로봇 작업에 활용한다는 점이 흥미롭다. 다만 물체의 의미를 잘 안다고 새로운 동작 기술까지 자동으로 생기는 것은 아니다. 공식 시연에서 된 작업과 우리 로봇에서 가능한 작업도 구분해야 한다.

참고: [RT-2 공식 프로젝트](https://robotics-transformer2.github.io/).

## OpenVLA — 출력보다 행동 복원 과정을 봐야 함

OpenVLA(2024)는 코드와 가중치가 공개된 VLA다. 교안의 기본 모델 구조는 다음과 같다.

```text
영상 → DINOv2·SigLIP → MLP Projector ┐
                                    ├→ Llama 2 7B → 행동 토큰 → 행동 복원
언어 지시 → Tokenizer ──────────────┘
```

시각 인코더가 뽑은 영상 특징을 Projector가 언어 모델에 연결한다. 모델은 관측과 지시를 바탕으로 행동 토큰을 예측한다. 코드를 볼 때는 모델 호출 한 줄보다 **영상 전처리·행동 역정규화·로봇별 통계**를 확인하는 것이 중요하다.

공식 예제의 `unnorm_key="bridge_orig"`는 행동을 복원할 데이터셋 통계를 지정한다. 다른 로봇에 이 키를 그대로 적용해도 된다는 뜻은 아니다. 코드 공개와 모델 가중치의 이용 조건도 별도로 확인한다. [OpenVLA 공식 코드·추론 예제](https://github.com/openvla/openvla).

| 비교 | RT-2 | OpenVLA |
| --- | --- | --- |
| 공통점 | 영상·언어를 행동 토큰에 연결 | 영상·언어를 행동 토큰에 연결 |
| 오늘 본 핵심 | 웹 지식과 로봇 시연을 함께 학습 | 공개 구조와 행동 복원 과정을 코드로 확인 |
| 적용할 때 | 학습한 행동과 적용 로봇의 차이 확인 | 전처리·통계 키·행동 규격부터 확인 |

### 우리 로봇에 연결한다면

교안의 7차원 행동 예시는 위치 3개·회전 3개·그리퍼 1개처럼 해석할 수 있지만, **7개 숫자라고 7개 관절각은 아니다.** 정확한 의미는 모델과 데이터셋 명세를 따라야 한다.

```text
카메라 영상·지시
 → 정책 출력
 → 역정규화
 → 좌표계·단위 변환
 → 현재 상태·제한값 검사
 → 로봇 실행
 → 결과 재관측
```

최소한 차원, m/mm·rad/deg, 기준 좌표계, 절대값/증분, 그리퍼 값의 의미, 실행 주기를 맞춰야 한다. 영상과 지시만 연결해 모든 로봇에서 바로 쓸 수 있는 구조는 아니다.

교안 뒤의 SmolVLA는 추론과 실행을 비동기로 나누는 관점도 소개한다. 행동을 큐에 넣더라도 관측 시각과 실행 시각이 너무 벌어지면 오래된 행동을 버리는 기준이 필요하다. Gemini Robotics 등 공식 시연도 지시·관측·행동 순서를 읽는 자료로 보고, 자체 장비의 성공률로 받아들이지는 않는다.

## 중간에 헷갈렸던 개념

### 합성곱·ReLU·Pooling·Softmax는 어디가 다른가?

| 연산 | 역할 | 간단한 예 |
| --- | --- | --- |
| 합성곱 | 작은 필터의 가중합으로 국소 특징 추출 | 선·모서리·무늬에 대한 특징 맵 |
| ReLU | 비선형 변환 | `[-2, 3] → [0, 3]` |
| Max Pooling | 주변 값을 요약해 공간 크기 축소 | `[[1,4],[2,3]] → 4` |
| Softmax | 클래스 점수를 합이 1인 값으로 정규화 | logit → 클래스별 예측값 |

합성곱 필터는 학습으로 바뀐다. 일반적인 ReLU·Pooling에는 학습할 가중치가 없다. Softmax 값이 높아도 실제 정답을 보장하지 않으며, PyTorch의 `CrossEntropyLoss`에는 보통 Softmax 전 logit을 넣는다.

합성곱의 한 축 출력 크기는 dilation=1일 때 다음과 같다.

$$N_{out}=\left\lfloor\frac{N+2P-K}{S}\right\rfloor+1$$

32×32 입력에 K=3, P=1, S=1이면 32×32가 유지된다. 교안의 `Conv2d(3,8,3,padding=1)`은 `[1,3,32,32] → [1,8,32,32]`로 공간 크기는 유지하고 채널을 바꾼다.

CNN 분류는 영상의 범주를 고르는 일이다. CLIP은 영상·문장의 유사도를 비교하고, BLIP은 캡션·답변을 만든다. 어느 쪽도 그 결과만으로 집기용 3D 좌표가 나오지는 않는다. 검출·깊이·보정·좌표 변환이 더 필요하다. 분류 평가는 연속 촬영 장면을 학습·시험에 섞지 않고 오분류와 혼동행렬을 함께 본다.

### Qwen·Node.js·RAG

- **Qwen:** 모델 계열 이름. 소스 코드는 실행 방법이고 가중치는 학습된 파라미터다. 공개 가중치로 추론할 수 있어도 모델별 사용 조건은 확인해야 한다. [공식 저장소](https://github.com/QwenLM/Qwen3).
- **Node.js:** JavaScript를 브라우저 밖에서 실행하는 환경. 에이전트의 모델 호출·도구 실행을 조율하는 프로그램에 사용할 수 있다. AI 모델 자체는 아니며 Python으로도 에이전트를 만들 수 있다. [공식 소개](https://nodejs.org/learn/getting-started/introduction-to-nodejs).
- **RAG:** 관련 문서를 검색해 질문과 함께 모델에 넣는 검색 증강 생성. 학습하지 않은 매뉴얼도 참고하게 할 수 있지만, 가중치에 영구 학습하는 것은 아니다. 검색 누락과 답변 오류는 여전히 남는다. 매뉴얼 검색으로 실시간 로봇 상태 확인을 대신할 수도 없다. [참고 문헌](https://arxiv.org/abs/2407.13193).

## 로컬 실행에서 막히면

교안 35쪽의 오류 진단도 단계별로 나눠 봐야 한다.

- 연결 거부 → 서버·주소·포트.
- 모델 없음 → 모델 태그·다운로드 여부.
- 시간 초과 → 최초 로딩·문맥 길이·장비 부하.
- JSON 오류 → 파싱·구조 검사.
- 의미 오류 → 실제 대상·장소·현재 상태 검사.

실패하면 실행을 보류하고 원인과 경과 시간을 남긴다. 오늘은 개념과 적용 경로를 정리한 것이며 RT-2·OpenVLA의 로봇 실행이나 성능 측정을 한 것은 아니다.
